Eight metrics are available: recorded assessment scores, completed assessment activity, finding discoveries, recorded resolutions, current unresolved severity, finding workflow status, finding categories, and remediation task status. Temporal metrics support line/bar/area; categorical metrics support bar/donut. CyphBot can choose up to six charts, add or remove charts, hide summary cards/supporting tables, change the heading, filter finding severities, and select any rolling 1–365-day period. An ordinary full report defaults to three charts.

Hover over a point, bar, area or donut segment, or tap it on mobile, to see its observation and value in a floating tooltip. The Data tab includes the same plotted values and optional supporting tables, up to 20 priority findings and 60 completed assessments. JSON downloads the complete typed report; each chart exports PNG, and each table exports CSV. Counts come from the selected organization's database rows. No performance numbers or trend points are generated by a language model.

## Architecture

- The existing authenticated chat endpoints remain in use. A local development flag routes report requests to a tenant-scoped, repeatable-read, read-only snapshot with SQL timeouts and bounded result lists.
- SSE carries an assistant thinking status, a keyed `artifact-status`/completed `artifact` part for report actions, and separate model-written answer text. Structured AI planning completes before the answer is delivered; this local path does not stream partial model JSON or claim token-by-token upstream streaming. Incomplete chart JSON never enters the Markdown renderer.
- Pydantic validates the server contract. A closed Zod representation validates the client payload before render. Host code alone compiles the permitted points and chart kinds into Vega-Lite. Raw Vega/HTML, external data URLs, model expressions, scripts and arbitrary config fields are not accepted.
- Vega 6.4.0, Vega-Lite 6.5.0, and vega-interpreter 2.2.1 are pinned. Vega parses ASTs and evaluates via the interpreter. No View/library objects are exposed on `window`; the chart loader rejects HTTP/files/resources. Report rendering is lazy-loaded (about 274 KB gzipped in this prototype).
- React renders labels/tables as text. CSV exports escape formula-leading text cells. Client validation checks the artifact's organization against the active workspace. In-flight responses are aborted/ignored after conversation reset, unmount or organization change.
- Versions are immutable snapshots held **in memory for this tab only**. Reload resets the conversation and versions. This is deliberately not a database artifact store, share system, or production retention policy.
- Both `CYPHWARD_ARTIFACT_LAB=true` and `CYPHWARD_ENV=development`, plus a local database destination, are required by the server. The frontend suggestion is controlled by `VITE_CYPHWARD_ARTIFACT_LAB=true`. Production remains off even if the feature flag is accidentally set there.

This follows the user's report at `/home/consigliere/reports/Chat artifact rendering design.md` and source notes at `/home/consigliere/research_notes/Chat artifact rendering design/`: typed view, separate panel, stable IDs, append-only versions, static export, and no arbitrary-code sandbox. It keeps Cyphward's existing SSE rather than introducing AI SDK RSC, MCP Apps or a new chat framework. The bounded intermediate representation is stricter than accepting arbitrary Vega-Lite JSON. Interpreter setup follows the [Vega documentation](https://vega.github.io/vega/usage/interpreter/), and compilation follows the [Vega-Lite documentation](https://vega.github.io/vega-lite/usage/compile.html).
